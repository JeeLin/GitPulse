# v0.2.0: 配置管理面板

## Context

M1（v0.1.0 本地核心闭环）已完成，8 步 dev-flow 全部通过。M1 的配置管理仅支持手编 `~/.gitpulse/config.toml`，首启动 0 仓库时仪表盘为空且无引导，是一个真实体验缺口。本里程碑补齐程序内配置管理能力。

版本类型：minor（新功能）
里程碑起始 ref: e032ee9

## 产品边界

**做**：
- 仪表盘空态引导：扫描到 0 仓库时显示提示文案与入口键位
- 配置管理面板（`View::Config`）：查看 scan_dirs 列表、添加目录、删除目录
- 添加目录：输入路径 → 校验（存在性/去重）→ 持久化到 config.toml → 自动重扫
- 删除目录：选中 → 确认框（y/n）→ 持久化 → 自动重扫
- dashboard 新增 `c` 键进入配置面板

**不做**：
- 不改 M1 已有功能（仪表盘、单仓库、diff、commit、push/pull、分支面板）
- 不涉及远程 API
- 不改配置文件格式（仍为 `scan_dirs: Vec<PathBuf>` TOML）

**流程约定的附带 docs 变更**（属规划同步，非功能范围）：
- `docs/DEVELOPMENT.md` 新增 M1.2 里程碑整节、调整 M3 子任务表；`docs/PRODUCT.md` 新增 M1.2 行——里程碑规划自动同步（步骤1 里程碑文档的一部分），纯文档无功能影响
- `docs/BUGS.md` 缺陷池登记（本里程碑发现但不修复的非 UTF-8 持久化限制）

## 子任务详细设计

### 1 仪表盘空态引导

- **功能目标**：当 `scan_dirs` 为空或扫描到 0 仓库时，在仪表盘中央显示引导提示，告知用户如何配置
- **文件结构**：修改 `src/ui/dashboard.rs`
- **交互设计**：空态时仪表盘主体区域替换为居中提示文案「暂无仓库 — 按 c 管理扫描目录」（中性文案：扫描目录为空或已配置目录无仓库均适用）；非空时保持原有仓库列表不变
- **测试标准**：dashboard 渲染测试：空 repos 时 buffer 包含引导文案；非空时不含引导文案
- **提交信息**：`feat(config): add dashboard empty state hint for unconfigured scan dirs`

### 2 配置视图骨架

- **功能目标**：新增 `View::Config` 视图，展示当前 scan_dirs 列表，支持 j/k 导航，dashboard 按 `c` 进入，`Esc` 返回
- **文件结构**：新建 `src/ui/config.rs`；修改 `src/app.rs`（View 枚举、状态字段、handle_key）；修改 `src/ui/mod.rs`（dispatch）
- **接口设计**：
  - `App` 新增字段：`config_state: ListState`
  - 方法：`enter_config()` / `leave_config()`
  - `View::Config` 键位：`j/k` 导航、`a` 进入添加模式、`d` 进入删除确认、`Esc` 返回、`q` 退出程序
- **交互设计**：面板标题「扫描目录配置」，底部键位提示行 `j/k 选择  a 添加  i 手动  d 删除  Esc 返回`，列表显示每行目录路径，当前选中高亮
- **测试标准**：状态机测试（enter_config/leave_config/键位路由）+ render 测试（标题/列表/键位提示）
- **提交信息**：`feat(config): add config view skeleton with list display and key routing`

### 3 添加目录

- **功能目标**：在配置面板按 `a` 打开目录选择器（des-1）浏览并回车选取，或按 `i` 弹出手动输入框键入路径，校验后保存并重扫
- **文件结构**：修改 `src/app.rs`（输入状态、submit_config_add、校验逻辑、picker 流程）；修改 `src/config/mod.rs`（激活 `Config::save`）；修改 `src/ui/config.rs`（输入模式与目录选择器渲染）
- **接口设计**：
  - `App` 新增字段：`show_config_input: bool`、`config_input: String`
  - 方法：`start_config_add()` → 打开目录选择器（des-1）；`start_config_manual()` → 打开手动输入框（设置 `show_config_input=true` 并清空 `config_input`）；`cancel_config_add()` → 关闭输入框
  - 目录选择器（des-1）：`start_config_picker()` / `picker_submit()` → 选中条目走同一 `add_scan_dir`（`PathBuf` 无损传递）
  - 移除 `Config::save` 上的 `#[allow(dead_code)]`
- **交互设计**：输入模式下顶部显示「添加扫描目录」，输入框显示已输入内容+光标，底部提示 `Enter 确认  Esc 取消`
- **校验规则**：
  - 空路径 → `set_error("目录不能为空")`
  - 路径不存在 → `set_error("目录不存在: {path}")`
  - 非目录 → `set_error("不是目录: {path}")`
  - 已在列表中 → `set_error("目录已在列表中")`
  - 成功 → `set_info("已添加扫描目录: {path}")` + refresh_repos
- **测试标准**：添加成功/各校验失败/保存持久化测试
- **提交信息**：`feat(config): add scan dir with validation and persistence`

### 4 删除目录

- **功能目标**：在配置面板按 `d` 弹出确认框，确认后删除选中目录并保存
- **文件结构**：修改 `src/app.rs`（删除确认状态、confirm_config_delete）；修改 `src/ui/config.rs`（确认框渲染）
- **接口设计**：
  - `App` 新增字段：`show_config_delete_confirm: bool`
  - 方法：`confirm_config_delete()` → remove selected + save + refresh_repos + clamp selection
  - `cancel_config_delete()` → 清除确认状态
  - 空列表时按 `d` → `set_error("没有可删除的目录")`
- **交互设计**：确认模式下覆盖层显示「移除该目录？y 确认 n 取消」
- **测试标准**：删除成功/取消/空列表报错/保存持久化测试
- **提交信息**：`feat(config): add scan dir removal with confirmation`

## 设计核对点

- [ ] 配置面板入口：dashboard `c` 键，底部键位提示行包含 `c 配置`
- [ ] 空态引导文案清晰，用户首次启动即可在程序内完成配置
- [ ] 添加目录校验完整（存在性/类型/去重），错误信息红显
