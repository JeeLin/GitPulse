# GitPulse 交互设计规范（Design Spec）

> 本文档从第一性原理定义 GitPulse 的完整交互系统。**只描述设计，不含实现。**
> 平台约束：ratatui / 终端 / 纯键盘 / 仅在输入时重绘 / 宽度 80–120 列 / CJK 占 2 格 / 每一行必须能放下或省略号截断 / 同一时刻只有一个焦点 / 单二进制。

---

## 0. 设计总纲：一套语法，而不是一堆例外

整个应用只有**四条全局不变的动词**，其余一切行为都建立在这四条之上：

| 键 | 动词 | 含义 |
|----|------|------|
| `Enter` | **打开** | 打开当前焦点项：压入子屏 / 打开模态框 / 确认模态框中的按钮 |
| `Esc` | **返回** | 弹出一层屏 / 关闭模态框 / 取消输入 |
| `q` | **退出** | 退出整个应用 |
| `Ctrl-C` | 强制退出 | 终端惯例，任何时刻生效 |

辅动词（作用于焦点，不改变栈语义）：

| 键 | 作用 |
|----|------|
| `Tab` / `BackTab`(Shift-Tab) | 在**当前屏**的多个面板间循环焦点 |
| `<` `>` | 在**当前屏**的多个上下文标签间横向切换（不入栈） |
| `r` | 重新加载当前视图（重跑该视图的数据拉取） |
| `j`/`k` 或 `↑`/`↓` | 在焦点列表内移动光标 |
| `g`/`G` 或 `Home`/`End` | 跳到列表首 / 尾 |
| `/` | 在焦点列表内搜索 / 过滤 |
| `n` | 新建（分支、标签、扫描目录等），一律走模态输入框 |
| `d` | 删除，一律先弹确认框，绝不直接执行 |
| `s`/`u` | 暂存 / 取消暂存（工作区文件） |
| `c` | 提交（打开提交信息模态框） |
| `p`/`P` | 推送 / 拉取 |
| `?` | 帮助浮层 |
| `Ctrl-P` | 命令面板：跳转到任意屏 |

## 1. 信息架构与导航树

### 1.1 导航模型：线性栈 + 上下文标签 + 面板焦点

三个正交的导航维度，语义互不重叠，因此"返回"永远只有一个意思：

1. **栈（纵向，父子）** —— `Enter` 压栈、`Esc` 弹栈。这是唯一会改变"返回去哪"的导航。
2. **上下文标签（横向，兄弟）** —— 同一屏内并列的子视图（如仓库屏的 工作区/分支/历史/标签/远端）。用 `<`/`>` 切换。**不入栈**，`Esc` 不会"退回上一个标签"。
3. **面板焦点（屏内布局）** —— 同一上下文里的多个可聚焦区域（列表 + 预览）。用 `Tab`/`BackTab` 切换。**不入栈**。

> **铁律**：只有"钻入一个条目"才入栈。切换标签、切换面板焦点都不入栈。因此 `Esc` 的行为在任何屏、任何上下文里都完全一致。

**这三个维度就是全部——不设第四维。** 面板**内部**的状态改变（折叠分组、展开日志、过滤列表）既不入栈、也不换上下文标签、更不移动面板焦点，因此不与上述三维语义重叠，也不构成新维度：它改变的是"这个面板画什么行"，不是"我在哪、焦点在哪"。把它做成维度会让 `Esc` 多出一层意思，而这正是本节铁律要排除的事。§6.1 的分组折叠是这一归位的标准样例。

### 1.2 导航树

```
仪表盘 (root, 栈深 1)
├─ 仓库工作区                      [Enter on 仓库行]
│  ├─ 上下文: 工作区 │ 分支 │ 历史 │ 标签 │ 远端
│  ├─ Diff 查看                    [Enter on 文件行]        (子屏, 栈+1)
│  ├─ 分支创建 / 标签创建           [n]                     (模态, 不入栈)
│  ├─ 提交详情                     [Enter on 提交行]        (子屏, 栈+1)
│  └─ PR / Issue / 通知 详情        [Enter on 条目行]        (子屏, 栈+1)
├─ 远端中心                        [Enter on 远端中心入口]   (栈+1)
│  ├─ 上下文: PR │ 检查 │ 问题 │ 通知
│  └─ PR / Issue / 通知 详情        [Enter]                 (子屏, 栈+1)
├─ 配置                            [Enter on 配置入口]      (栈+1)
│  └─ 扫描目录列表
└─ 帮助 / 命令面板                 [? / Ctrl-P]            (浮层, 不入栈)
```

栈深通常 ≤ 3。头部永远显示面包屑，强化"我从哪来"：

```
仪表盘 › 我的仓库 › GitPulse › 分支
```

在栈深 = 1（根屏）按 `Esc`：不退出，而在状态行短暂提示「已在顶层」（300ms 级，随后清空）。**退出永远由 `q` 负责。**

### 1.3 一致的"进入/离开"规则

| 场景 | 键 | 结果 |
|------|----|------|
| 列表行 | `Enter` | 压栈打开子屏 / 打开模态 |
| 模态框按钮行 | `Enter` | 确认该动作 |
| 子屏 / 模态 | `Esc` | 弹栈 / 关闭（不改变父屏栈） |
| 任意屏 | `q` | 退出应用（模态内 `q` 是字面字符，见 §2.4） |
| 列表行 | `d` | 打开确认模态（永不直接执行） |
| 任意屏 | `r` | 重新加载当前视图 |

## 2. 交互语法

### 2.1 全局键 vs 视图键

- **全局键**（`Enter`/`Esc`/`q`/`Ctrl-C`/`Tab`/`<`/`>`/`r`/`?`/`Ctrl-P`/`j`/`k`/`g`/`G`/`/`）在**所有屏**行为一致，永不被视图覆盖。
- **视图键**（`s`/`u`/`c`/`p`/`P`/`n`/`d` 等字母动词）只在拥有该动作的视图里有意义，其余视图按字面处理或忽略。
- 焦点在**输入模态框**里时，除 `Enter`/`Esc`/`Tab`（字段间移动）外，所有键都是**字面输入**（包括 `q`、`r`、`j`）。

### 2.2 规范键位（canonical）

| 用途 | 键 |
|------|----|
| 选择 / 移动光标 | `j` `k` `↑` `↓` |
| 打开 | `Enter` |
| 返回 | `Esc` |
| 退出应用 | `q` |
| 刷新 | `r` |
| 新建 | `n` |
| 删除 | `d`（先确认） |
| 切换上下文标签 | `<` `>` |
| 切换面板焦点 | `Tab` / `BackTab` |
| 搜索 / 过滤 | `/` |
| 帮助 | `?` |
| 命令面板 | `Ctrl-P` |

### 2.3 提示行（hint row）——唯一格式、唯一位置

- **全应用只有一条提示行**，固定在**屏幕最底一行**（footer 第 2 行），**永远 1 行高，永不移动、永不改变高度**。
- 固定顺序，从左到右：
  1. **全局段（永不截断）**：`⏎ 打开  Esc 返回  r 刷新  q 退出`
  2. **视图段**（当前焦点面板的专属动词，按重要性排序）
  3. **末段**（仅当该屏 >1 面板或 >1 上下文标签时）：`Tab 面板` / `< > 切换`
- 视觉：键名用 `key` 样式（加粗 + `accent` 色），动作用 `fg_muted`，段间用两个空格分隔。
- **截断规则**：左对齐的全局段永不截断；视图段与末段在宽度不足时从右往左用 `…` 省略。宽度预算见 §5.4。

### 2.4 模态 / 浮层行为

- **模态框**（commit、分支创建、标签创建、删除确认、路径输入、命令面板、帮助）：居中盒体，固定最小/最大尺寸，`surface` 底 + 圆角边框 + 居中标题。
- 背景处理：ratatui 无真透明度。妥协方案：模态区域清空并绘制实心底色；背景其余部分**保留原内容**或替换为暗化变体（用 `surface` 覆盖）。视觉上以**边框高亮 + 标题**为主焦点信号。
- **同时只允许一个模态**（单焦点）。模态不能打开模态。若某动作在模态中需要二次确认，应：关闭模态 → 执行 → 状态行反馈结果。
- 模态键位：
  - 文本输入：所有键字面输入；`Enter` 确认；`Esc` 取消。
  - 多字段模态：`Tab`/`BackTab` 在字段间移动；`↑`/`↓` 在下拉 / 列表字段内移动。
  - 列表型模态（如命令面板）：`j`/`k` 选择，`Enter` 执行，`Esc` 关闭。
- 模态关闭不改变栈深（它从未入栈）。

## 3. 焦点与状态模型

### 3.1 焦点

- **同一时刻只有一个焦点面板。** 焦点面板边框用 `border_focus`（accent），非焦点面板边框用 `border`（muted）。
- **光标只存在于焦点列表面板**的 `ready` 状态中。`loading`/`empty`/`error` 状态下无光标。
- 光标视觉：选中行用 `surface_alt` 底色，或行首 `▌` 标记 + accent 前景。二选一，全局统一（本规范定为：**行首 `▌` + `surface_alt` 底色**）。

### 3.2 列表面板的五态（每个列表面板都必须实现全部五态）

| 状态 | 形态（统一） |
|------|--------------|
| `loading` | 面板居中显示旋转字形 + 标签 `加载中…` + 可选副标签（如 `正在读取远端 PR…`）。边框与标题不变。无光标。 |
| `empty` | 面板居中显示标题 + 一行描述 + 主行动提示（如 `按 Enter 添加扫描目录`）。无光标。 |
| `error` | 边框块（`danger` 色），标题 `加载失败`，消息（最多 3 行，超出省略号），提示 `按 r 重试`。无光标。 |
| `ready` | 内容 + 光标（`▌` + `surface_alt`）。若有详情面板，详情面板展示光标行内容。 |
| `success-flash` | 等同 `ready`，但状态行显示瞬时绿色结果；若操作改变了列表，新/变更行短暂高亮（约 1s）后恢复。 |

### 3.3 覆盖面

以下每一类面板都采用上面同一套五态，不做特例：

仓库列表、文件状态列表、分支列表、标签列表、提交列表、扫描目录列表、PR 列表、检查列表、Issue 列表、通知列表。

## 4. 状态反馈模型（异步结果 / 错误 / 进度）

### 4.1 页脚 = 两行（固定）

```
第 N-1 行:  状态行   ← 异步结果 / 进度 / 错误的唯一着陆点
第   N 行:  提示行   ← §2.3 的固定 hint row
```

页脚总高度恒为 2 行，永远存在，不随内容增减。

### 4.2 状态行的形态（对本地 git 与 GitHub 回执完全一致）

| 形态 | 样式 | 生命周期 |
|------|------|----------|
| `idle` | 空（或短暂显示上次结果后清空） | — |
| `progress` | `⠋ 正在推送… [origin/dev]`（`info` 色，可选旋转字形） | 操作结束自动替换 |
| `success` | `✓ 已提交 abc1234 · 3 个文件`（`success` 色） | 3s 自动清空，或被下一次状态变化覆盖 |
| `error` | `✗ 推送失败: 远端拒绝快进`（`danger` 色） | 保持到被 `Esc`/`r` 消除或被新状态覆盖 |
| `info` | `已切换到分支 dev`（`fg_muted`） | 3s 自动清空 |

### 4.3 两种错误面，一条规则

- **加载失败**（拉取 PR 列表失败、读仓库状态失败）→ 用**面板 `error` 五态**（持久、可 `r` 重试），因为它是"这块内容没加载出来"，不是一次操作的结果。
- **操作结果**（commit/push/pull/stage/删除标签 等你主动触发的动作）→ 用**状态行**（瞬时），因为它是"你刚才那个动作怎么样了"。

> 规则：**加载失败 → 面板 error 态；操作结果 → 状态行。** 两个面、一条规则，对本地 git 与 GitHub 回执一视同仁。

### 4.4 进度与重绘限制

- 平台是**仅在输入时重绘**。因此进度旋转字形不能实时自转。
- 妥协：进度字形仅在**有输入/事件到达时**步进；若长时间无输入则静止在某一帧。标签文字 `正在推送…` 仍准确表达"进行中"。
- 长时间异步操作期间，焦点面板内容不被清空（保留旧数据 + 状态行进度），避免闪烁。

## 5. 视觉 Token 系统

### 5.1 颜色角色（暗色主题）

| Token | 值 | 用途 |
|-------|-----|------|
| `bg` | `#1a1b26` | 应用背景 |
| `surface` | `#24283b` | 面板背景 / 模态底 |
| `surface_alt` | `#2f3349` | 选中行底 / 交替行底 |
| `border` | `#414868` | 非焦点边框 |
| `border_focus` | `#7aa2f7` | 焦点边框 |
| `fg` | `#c0caf5` | 主文本 |
| `fg_muted` | `#565f89` | 次级文本 / 提示 / 未激活 |
| `accent` | `#7aa2f7` | 选中 / 键名 / 活动标签 |
| `success` | `#9ece6a` | 成功 / 新增 |
| `danger` | `#f7768e` | 错误 / 删除 |
| `warning` | `#e0af68` | 修改 / 警告 / CI pending |
| `info` | `#7dcfff` | 重命名 / 哈希 / 进度 |
| `git_add` / `git_mod` / `git_del` / `git_renamed` | `success`/`warning`/`danger`/`info` | 文件状态着色 |
| `ci_pass` / `ci_fail` / `ci_pending` / `ci_skip` | `success`/`danger`/`warning`/`fg_muted` | CI 状态着色 |

### 5.2 间距节奏

- 全局水平内边距：面板内左右各 1 列。
- 面板间沟槽：1 列。
- 垂直结构（自上而下）：标题行 1 + 上下文标签行 1 + 内容区（弹性）+ 状态行 1 + 提示行 1。
- 标题行：左 = 视图标题，中 = 面包屑，右 = 元信息（分支 / 领先落后 / 远端徽标）。

### 5.3 边框 / 标题 / 字体角色

- 每个面板：单线圆角边框（`╭─╮` 等），标题左上角内缩 1 格，用该面板边框色渲染（焦点 = accent）。
- 模态：同款边框，标题居中。
- 字体角色：
  - `title`：加粗，accent/fg
  - `heading`：加粗
  - `body`：常规
  - `caption`：`fg_muted`，弱视觉权重
  - `key`：加粗 + accent（提示行 / 键帽）
  - `code`：等宽（哈希、分支名），哈希用 `info`

### 5.4 省略 / 宽度预算规则（硬约束）

- 每一行按**显示单元格宽度**累加布局（CJK = 2，ASCII = 1，常见 emoji = 2）。
- 内容超出区域时截断，末尾追加 `…`（占 1 格）。
- **单行永不换行**（列表行、提示行、状态行、标签行、标题行）。仅在指定的多行详情区（PR 正文、提交正文、Issue 正文、diff 上下文）允许换行，并可滚动。
- 列表表格列宽：定义每列 `min_width` + 优先级，宽度不足时**低优先列先消失**（不是缩小），保证高优先列可读。
- **Author 列**（§6.1，v0.9.0）为**低优先**列：`min_width` = 12 格（`user.name` 省略后），窄屏（80 列下分栏后不足 28 格的列表）**整列消失**而非缩小。它列于 `Remote` 之后，即全表最低优先级——与「身份列最不承担识别职责」一致。
- **组头行**（§6.1.1）同样单行、永不换行，溢出末尾 `…`。其宽度优先级反向于表格：**折叠字形 `▸`/`▾`（1 格）与计数 `(N)` 是固定家具，必须在任何宽度下保住**，组名吸收全部余量并按本节规则省略。理由：丢掉字形的组头行不再说明这一段是开还是合，丢掉计数则让"下面还藏着几个仓库"无从读出——两者都是组头行存在的意义，而组名随时可由分组配置复原。
- **80 列临界地板**下的侧栏拆分规则：**仅当两个面板都能保住各自 `min_width`（列表 ≥28，详情 ≥32）时才允许左右分栏**；否则回退为上下堆叠或"列表 + 焦点时内联预览"。上下文标签行在 ≥80 列始终可见。

## 6. 各视图交互设计

> 每个视图给出：布局、键位、提示行内容、全部状态。提示行格式统一见 §2.3，只列差异段。

### 6.1 仪表盘（Dashboard，根屏，栈深 1）

**布局**
```
┌ 标题: GitPulse          面包屑: 仪表盘          右: 仓库数/远端徽标 ┐
│ 上下文标签: 仓库 │ 远端中心 │ 配置                                     │
│ ┌───────────────────────────────────────────────────────────────┐ │
│ │ 仓库列表（焦点面板）                                          │ │
│ │  ▌ GitPulse      main    ↑2 ↓0   ●3  ⚠1   远端: GitHub  张三  │ │
│ │    foo           dev     ↑0 ↓0   ●0  ⚠0   远端: GitHub  无    │ │
│ │    bar           main    ↑1 ↓0   ●2  ⚠0   远端: 无       李四  │ │
│ │                                                               │ │
│ │ (或: 预览面板 / 空态 / 错误态)                                 │ │
│ └───────────────────────────────────────────────────────────────┘ │
│ [状态行]                                                          │
│ [提示行] ⏎ 打开  Esc 返回  r 刷新  q 退出  …  Tab 面板  < > 切换  │
└───────────────────────────────────────────────────────────────────┘
```

**上下文标签**：`仓库` `远端中心` `配置`（`<`/`>` 切换，等价于 Tab 切面板）。
**面板**：仓库列表（主）+ 可选预览面板（窄屏隐藏）。

**列表列**（§5.4 表格列宽）：`▌` 光标 | 名称 | 分支 | 脏文件数（`●`）| 冲突数（`⚠`）| 领先/落后（`↑N↓M`）| `远端: <平台>` | **作者**（v0.9.0）。

**Author 列**（v0.9.0）：显示该仓库**生效的 `user.name`**——即 `git commit` 在这个仓库里真实采用的提交者。取值来自 local→global→system 的 git2 解析（与 `src/git/commit.rs` 同一套 fallback），因此**列里看到的就是提交会用的身份**。解析不出时显示 `无`（同 `远端: 无`，不是错误态）。邮箱不进此列——`名字 <邮箱>` 的完整形态在提交弹窗标题回显（§6.2.1），该列只留名字以守住 §5.4 的 12 格预算。该列为全表最低优先级，窄屏整列消失。

**键位**
| 键 | 动作 |
|----|------|
| `j`/`k` | 移动仓库光标 |
| `Enter` | 打开选中仓库 → 仓库工作区（栈+1）。落在组头行上为**空操作**，不改变当前仓库 |
| `r` | 重扫所有扫描目录 + 重拉远端 |
| `n` | （在配置上下文中）添加扫描目录 |
| `z` | 折叠 / 展开光标所在的分组（见 §6.1.1） |
| `Ctrl-P` | 命令面板 |

**提示行视图段**：`⏎ 进入仓库  n 添加目录  z 折叠分组`。其中 `z 折叠分组` **仅在配置了 `scan_groups` 时出现**——未配置分组时 `z` 无可折叠的段、按 §6.1.1 是空操作，广告一个不派发任何动作的键即 §2.3 的死键（B7-01）。

**状态**
- `loading`：居中 `正在扫描仓库…`
- `empty`：`还没有仓库` + `按 n 添加扫描目录，或按 ? 查看帮助`（首启动引导）
- `error`：`扫描失败: 权限不足` + `按 r 重试`
- `ready`：列表 + 光标
- `success-flash`：批量 pull/fetch 完成后状态行 `✓ 已更新 3 个仓库`

#### 6.1.1 扫描目录分组（组头行）

仓库列表是**派生视图**，不是嵌套数据源：配置里声明的分组决定列表画成什么样，仓库本体仍是扁平的。分组是可选配置——**未配置任何分组时列表与本节其余部分逐字相同**，不渲染任何标题行、不改变行序。未归入任何分组的仓库排在所有分组之后，且**不带标题行**：它不属于任何一段，给它安一个名字就是撒谎。

**行形态**
```
▾ work (3)        ← 展开
│  ▌ GitPulse     main    ↑2 ↓0   ●3  ⚠1   远端: GitHub
│    dotfiles     main    ↑0 ↓0   ●0  ⚠0   远端: GitHub
│    playground   dev     ↑0 ↓1   ●0  ⚠0   远端: 无
▸ oss (4)         ← 折叠：(4) 是藏起来的仓库数
▸ personal (2)    ← 折叠
    scratch       main    ↑0 ↓0   ●0  ⚠0   远端: 无   ← 无归属，不带组头
```
- 展开态 `▾ 组名 (N)`，折叠态 `▸ 组名 (N)`；字形各占 1 格。
- 组头行用 §5 token：折叠字形 `accent`，组名与计数 `fg_muted`。禁裸色值。
- 组头占**一行**，因此它与仓库行受同一套 §3.1 选中态规则：光标停在组头上时，该行照常画 `▌` + `surface_alt`。组头是否带光标由**光标位置**决定，不由行的类型决定。

**计数格式**：`N` 是该组内**可见**仓库数，不是分组的生命周期总数。因此折叠态的 `▸ oss (4)` 读作"下面还有 4 个"，而不是"这一段变小了"。

**可选择性**：组头行**不是可打开的目标**。`Enter` 落在组头上是**空操作**——不压栈、不改变当前仓库、不关任何东西；预览面板与命令面板同样把它读作"当前没有选中仓库"。理由是 §1.1 的铁律——`Enter` 的含义只有"打开"一个，若组头可开，它就得凭空发明第二件可打开的事，或让 `Enter` 在"无反应"与"打开"之间二义。折叠的入口因此是 `z` 而非 `Enter`。

需要分清两层：光标是**行**光标，`j`/`k` 逐行移动、可以停在组头上；「不可选中」约束的是行的**可打开性**，不是光标能否落上去。把光标钉死跳过组头会让 `z` 无法就地作用于组头，反而多出一条专用键。

**折叠键位**：`z`（fold）。不用 `Tab`——§0 的辅动词已把它固定为面板焦点；也不用 `z` 以外的新全局键，折叠只是仪表盘仓库上下文里的呈现动作，按 §2.1 属**视图键**。`z` 作用于**光标所在的分组**：光标在组头上就折叠该组，在组内仓库上就折叠它所属的组。未配置分组、或光标落在无归属的仓库上时为**空操作**（没有可折叠的段）。折叠会缩短行数，故动作后光标按 §3.2 `ready` 态夹到最后一个真实行，不悬在空处。按 §2.3，有派发的键必须出现在本屏提示行，故配置了分组时视图段含 `z 折叠分组`；反向亦然——提示行广告的键在该屏必有派发，故未配置分组时该段**不得**出现 `z`（否则广告的键派发不出任何可观测变化）。

**折叠态持久性**：**仅存在于内存，重启后全部展开**。折叠是纯呈现态，不写回配置、不跨会话保留——它不改变用户看见了什么数据，只改变一次会话内的取景，持久化只会把一个临时手势固化成必须迁移、必须解释的隐藏状态。配置里没有这个键，规范里也不给它留位置。

**与五态的关系（§3.2 / §4.3）**
- `loading` / `error` / `empty`：面板整体被状态层替换，**一个组头行都不画**。五态优先于分组。
- **某分组下仓库已全部消失**（配置改过、目录被删）：**不渲染该组头行**，该组在行集合里彻底不存在——渲染一个空壳标题会让"这一段是空的"与"这一段不存在"读起来一样。全部仓库都没了时，面板回落 `empty`；只是某一段空掉，其余分组与其行照常。
- 分组配置整体非法（重复组名、前缀为空或互相矛盾、配置解析失败）：按 §4.3 落**面板 `error` 态**（持久、给 `r 重试`），**不得**只在状态行闪一行——那会把"分组根本没生效"藏进一条转瞬即逝的消息，用户只会看到一屏没分组的仓库，以为是自己配错了分组。错误消息须带配置 `path` 与出错条目，使人能定位到写坏的那一条。

|----|------|

**提示行视图段**：`⏎ 跳转  m 已读`

---

### 6.11 帮助浮层 / 命令面板（浮层，不入栈）

- **帮助（`?`）**：居中模态，展示当前屏的键位（复用 §2.3 的分段展示：全局段 + 视图段）。`Esc`/`q` 关闭。
- **命令面板（`Ctrl-P`）**：居中模态，模糊搜索所有可跳转目标（各屏、各仓库、各上下文标签）。`j`/`k` 选择，`Enter` 跳转（直接重设栈），`Esc` 关闭。

## 7. 迁移备忘（设计级，按用户痛感排序）

> 不涉及代码，只标注"当前实现若与本规范不一致，按痛感从高到低对齐"。

| 排序 | 痛点 | 规范要求 |
|------|------|----------|
| 1 | **"返回/退出"语义不统一**：不同屏 Esc/q 行为不一致，用户记不住 | §0/§1：`Esc`=返回栈、`q`=退出应用、根屏 Esc 不退出；模态内 q 是字面字符 |
| 2 | **提示行位置/格式漂移**：不同屏提示行高度、位置、分段不同，无法形成肌肉记忆 | §2.3：唯一格式、唯一位置（最底行、恒 1 行）、固定顺序（全局段永不截断） |
| 3 | **空态/错误态/加载态各自为政**：有些列表有空态提示，有些直接空白 | §3.2：每个列表面板统一五态（loading/empty/error/ready/success），错误态必须给出 `r 重试` |
| 4 | **异步反馈落点不一致**：commit 结果有时在标题、有时在弹窗、有时无反馈 | §4：操作结果一律走状态行（瞬时），加载失败一律走面板 error 态（持久），本地 git 与 GitHub 一致 |
| 5 | **CJK 宽度导致错位/截断失控**：行溢出、列错位、提示行被挤掉 | §5.4：按显示单元格宽度（CJK=2）预算，单行永不换行，低优先列先消失，80 列下保住 min_width 才分栏 |
| 6 | **导航维度混杂**：切面板与切标签都被当成"进入子页"，栈深失控 | §1.1：栈只由 Enter/Esc 驱动；`<`/`>` 标签与 `Tab` 面板焦点都不入栈 |
| 7 | **删除类操作缺确认**：分支/标签/丢弃直接执行 | §2.2/§6：`d` 一律先弹确认框 |
| 8 | **多仓库入口与单仓库远端回执割裂**：远端中心与仓库内远端列表长相不一 | §6.2.5/§6.3：远端中心与单仓库远端共用同一套列表/详情设计 |
| 9 | **进度不可感知**：长操作无任何进行中反馈 | §4.2/§4.4：状态行 progress 态 + 静态旋转字形（适配仅输入重绘） |
| 10 | **视觉层级弱**：焦点面板与非焦点面板边框同色，不知焦点在哪 | §3.1/§5.3：焦点面板边框用 accent，非焦点用 muted，光标统一 `▌`+`surface_alt` |
