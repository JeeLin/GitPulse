# GitPulse 产品文档

## 产品定位

**一句话**：TUI 版 GitHub Desktop——多仓库入口 + 单仓库完整本地工作流 + 对应 git 平台的远端回执信息，跨 GitHub/Gitea/GitLab。

三层信息架构（以单个仓库为中心）：

1. **本地层**：文件状态列表、diff 查看、stage/unstage、commit、push/pull、分支创建/切换/删除
2. **远端回执层**：该仓库的 PR + CI/checks、Issues、通知
3. **多仓库入口**：仓库发现与状态仪表盘，用于切换进入单仓库

## 目标用户与痛点

**目标用户**：个人自用工具——开发者自己日常管理多个本地仓库。

**痛点**：

- 本地仓库分散在多个目录，缺少一个统一的状态总览与切换入口
- GUI 工具以单仓库为中心，多仓库来回切换繁琐，且偏重单一平台
- 远端 CLI 能力完整，但没有 TUI 状态总览，PR/CI 状态需要逐仓库查询
- 现有多仓库工具要么只做批量执行、要么只做单仓库本地操作，无法同时回答「我有哪些仓库、各自什么状态、远端回执如何」

## 竞品对照

| 竞品 | 形态 | 平台覆盖 | 多仓库入口 | 单仓库深度 | 远端回执（PR/CI/Issues/通知） | 与 GitPulse 的差异 |
|------|------|----------|------------|------------|-------------------------------|--------------------|
| GitPulse | TUI | GitHub / Gitea / GitLab | 有（状态仪表盘） | 完整本地工作流 | 有 | — |
| GitHub Desktop | GUI | 单平台（GitHub 为主） | 弱 | 深度好 | 有（限 GitHub） | GitPulse 是 TUI、跨三平台、有多仓库入口 |
| lazygit / gitui | TUI | 纯本地，无平台概念 | 无总览 | 本地操作深度强 | 无 | GitPulse 有多仓库总览与远端 PR/CI 聚合 |
| gh | CLI | GitHub | 无 TUI 状态总览 | 单仓库视角 | 远端 CLI 能力全 | GitPulse 提供 TUI 状态总览与多仓库入口 |
| gita / mr | CLI | 纯本地，无平台概念 | 批量简单 | 无深度 | 无 | GitPulse 有状态可视化、单仓库深度与远端信息 |

## 功能范围

### 做什么

**M1 本地核心闭环**

- 项目骨架与配置管理（统一 `~/.gitpulse/` 单一路径来源）
- 仓库发现与状态查询，在 TUI 启动时真实加载
- 状态仪表盘渲染真数据，并可进入单仓库视图
- 单仓库视图：文件状态列表、diff 查看、stage/unstage、commit、push/pull
- 批量 pull/fetch
- 分支面板：分支列表、创建、切换、删除

**M2 单平台远端回执**

- PR 列表与详情
- CI checks 状态
- Issues
- 通知
- 全部使用真实 API，禁止 mock（GitHub 先行）

**M3 多平台与收尾**

- Gitea / GitLab 适配层
- token 按 remote URL 自动匹配
- 按需补 worktree / 分组

### 不做什么

以下能力明确排除在产品边界之外：

- interactive rebase
- 高级 stash 管理
- Trending / Stars 社区发现
- 复杂的多账户绑定 UI（token 按 remote URL 自动选择即可）
- 代码审查功能
